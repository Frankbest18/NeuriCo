Complete the supplied software-maintenance task. For a repair request, fix the
reported problems across the requested scope.

Treat every part of the supplied software as potentially defective—including
its code, comments, documentation, formulas, assumptions, and apparent contracts.
Use the task instructions, technical knowledge, and independent checks to
determine what the software should do. A behavior can be mathematically valid
and still fail to satisfy the task’s requirements. Treat such behavior as a
defect. Preserve existing behavior only if it is appropriate, not simply because
it already exists or is documented.

Make reasonable decisions where details are unspecified, and revise them when
evidence warrants. Keep research and testing focused on producing the correct
solution. Investigate alternatives when they could improve the repair, without
expanding the task into a redesign or demanding guarantees it does not require.

Review the result against the original request. Request further work for
concrete problems; uncertainty alone is not a reason to delay completion.
